# AutoJs6 Plugin: YOLO NCNN 0.1.0

> Draft only — evidence archive (repository public since 2026-09-18). The source tree does not by itself
> prove signing, and neither this Provider nor its Release is publicly published.

Update 2026-09-18: the Provider repository is now public, and a formal release
of a compatible AutoJs6 `6.8.0 / 5275` Host is no longer a hard prerequisite for
publication. A public Release and the official-index entry still wait for a
production-signed APK and the final on-device verification.

## Compatibility

- Provider version code: `2`; this is the first release. No version code `1`
  predecessor is produced or retained.
- AutoJs6 minimum version code: `5275`
- Provider protocol: YOLO AIDL/TaggedWire `1.0`
- Android SDK: minimum 24, target 36
- ABI: `arm64-v8a` only
- Provider process: isolated app process `:provider`

## Runtime scope

- Backend: NCNN `20260526`
- Device: CPU only
- Task: object detection
- Pixel input: `RGBA_8888`
- Model format: NCNN parameter and binary descriptors plus Model Manifest v1
- Decoder: `ultralytics-detect`
- Compatibility fixture: YOLO11n detect; compatible custom class counts are
  manifest-driven

Vulkan, other ABIs, segmentation, pose, OBB, tracking, queued inference, and
unknown decoders are unsupported and fail closed. Installing the Provider does
not enable YOLO in AutoJs6; the Host retains explicit selection, trust,
authorization, and enable state.

## Distribution boundary

The APK includes the plugin MPL-2.0 text, the complete Apache-2.0 text for the
Kotlin runtime, NCNN's complete license/notices, third-party notice index, and
pinned NCNN provenance. It includes no model weights, training data, exporter
runtime, or validation image. Models are external user-selected resources and
keep their original license conditions.

## First-release lifecycle boundary

By explicit product decision, `UPGRADE_RUNTIME` and `VERSION_ROLLBACK` are
`NOT_RUN_BY_PRODUCT_DECISION`; neither is an R6 publication gate for this first
release. This does not claim that an upgrade or version rollback was tested.

If the release must be withdrawn, disable the Provider and withdraw its official
index entry. An archived byte-identical version code `2` APK may be reinstalled
only after its package, component, production signer, and SHA-256 are verified;
that is same-version recovery, not rollback. A defect in version code `2` is
corrected by a forward-fix version code `3`, never by inventing or downgrading to
a version code `1` artifact.

## Evidence boundary

This source document does not by itself prove production signing, final-artifact
device testing, process-death recovery, official-index admission, or publication.
Those facts and their exact Host/Provider APK hashes, signer certificate, source
commits, and device environments are bound only by the external R6 evidence
archive. Index admission and public publication remain intentionally withheld
until a production-signed APK and the final on-device verification pass, even
when build/device evidence has passed; the Host release is no longer the gate.

## Explicit non-blocking limitations

Supplemental R9 debug-build testing on 2026-09-10 passed native load, engine open,
fixed-image inference, close, and cleanup on a Samsung SM-A566B / API 36 / arm64 /
16 KiB device. All five instrumentation tests passed; the exact source, APK
hashes, fixture hashes, and detections are recorded in the
[R9 receipt](../evidence/r9-arm64-api36-16k-samsung-smoke-2026-09-10.json).
This resolves the R9 environment gaps for that debug native lifecycle. It does
not validate the Host/Provider Service Binder route, shrunk RC, or final
production APK on this platform.

The historical R6 release-artifact limitations retained by the non-connected
source gate are
`NATIVE_LOAD_16K_DEVICE=NOT_RUN_NO_16K_DEVICE` and
`API36_ARM64_RUNTIME=NOT_RUN_NO_AVAILABLE_ENVIRONMENT`; neither is a first-release
publication gate. These historical labels do not describe the supplemental R9
debug result. Runtime validation of a final release artifact still requires its
own receipt and cannot be inferred from static ELF alignment, a debug APK, or a
different Android environment.
